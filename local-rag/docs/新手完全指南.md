## 第 0 章：用生活类比理解整个项目

想象你要应付一场「开卷考试」：


| 考试场景               | 本项目对应                      |
| ------------------ | -------------------------- |
| 书架上的课本             | `data/docs/` 里的 md/txt/pdf |
| 把课本撕成小纸条并编号        | **切片 Chunk**               |
| 给每张纸条贴「语义标签」（数字指纹） | **Embedding 向量**           |
| 把所有纸条和指纹存进抽屉       | **向量索引** `data/index/`     |
| 老师出题               | 用户提问                       |
| 按题意找出最相关的几张纸条      | **检索 Retrieval**           |
| 看着纸条答题，不许瞎编        | **LLM 生成 Generation**      |


**精髓一句话：**  
大模型不一定记得你的私有文档；RAG 就是**先查出相关原文，再让模型照着答**。

没有检索、直接问模型 = 闭卷（容易胡编）。  
有检索再问 = 开卷（可追溯来源）。

## 第 1 章：你必须先懂的基础概念

### 1.1 什么是 LLM（大语言模型）

就是会聊天的 AI（如 DeepSeek、GPT、Qwen）。  
它输入一串文字（Prompt），输出一串文字。

它**不会自动读你电脑上的文件**。你要把内容写进 Prompt 发给它。

本项目里：LLM 负责「组织语言回答」，不负责「从磁盘找文件」。

### 1.2 什么是 Prompt（提示词）

发给模型的整段指令 + 资料 + 问题。  
本项目在 `rag.py` 里拼出：

- 系统提示：你是谁、规则是什么（只根据资料答）  
- 用户消息：检索到的资料 + 问题

### 1.3 什么是 Token / 上下文窗口（了解即可）

模型一次能读的文字有限。  
所以不能把 100 本书全文每次都塞进去 → 才需要「先检索、只塞相关几段」。

### 1.4 什么是向量（Vector）与 Embedding

- **向量**：一串数字，例如 `[0.12, -0.03, …]` 共几百维。  
- **Embedding（嵌入）**：把一句话变成向量，使「意思相近的句子，向量也相近」。

类比：把文字投到一张「语义地图」上，相近意思落在相近位置。

### 1.5 什么是余弦相似度

衡量两个向量方向有多像。  
本项目对向量做了 **L2 归一化**，于是：

```text
相似度 = 向量 A · 向量 B   （点积）
```

分数越高，语义越相关。

### 1.6 什么是 RAG

**R**etrieval（检索）+ **A**ugmented（增强）+ **G**eneration（生成）

1. 检索：从知识库找相关片段
2. 增强：把片段塞进 Prompt
3. 生成：LLM 基于片段回答

### 1.7 什么是 API / 后端 / 前端（本项目形态）

- **后端**：Python 程序提供接口（FastAPI），干活（切分、检索、调模型）  
- **前端**：浏览器页面（HTML/JS），点按钮、发请求、显示结果  
- **API**：前后端约定的 URL，如 `/api/ask`

你打开网页 → JS 发 HTTP 请求 → Python 处理 → 返回 JSON → 页面展示。

### 1.8 什么是虚拟环境 `.venv`

Python 项目专用的「独立工具箱」，避免和系统其它包打架。  
`pip install -r requirements.txt` 就是往这个工具箱装依赖。

### 4.2 `ingest.py`：把文件变成「可检索小段」

**知识点：文档解析、文本清洗、Chunking。**

#### （1）支持哪些文件

```python
SUPPORTED_SUFFIX = {".txt", ".md", ".markdown", ".pdf"}
```

#### （2）怎么读出文字

```python
def read_file(path):
    # txt/md → read_text
    # pdf → PdfReader 逐页 extract_text
```

实现的功能：**统一变成纯字符串**，后面才能切片。

#### （3）怎么切片（最重要）

```python
def split_text(text, chunk_size=600, overlap=100):
    # 滑动窗口切分
    # 尽量在段落/句号处断开
    # 下一段回退 overlap，避免答案卡在边界
```

实现的功能：**长文 → 多个短 Chunk**。

为什么要切？

- 检索更准（整本书一个向量太「糊」）  
- Prompt 塞得下

##### 关键一行：`if cut >= chunk_size // 3`

切片时会先在当前窗口里找最后一个自然断点：

```python
window = text[start:end]
cut = max(window.rfind("\n\n"), window.rfind("。"), window.rfind("\n"))
if cut >= chunk_size // 3:
    end = start + cut + 1
```

含义拆解：


| 符号                | 意思                                                 |
| ----------------- | -------------------------------------------------- |
| `cut`             | 窗口内最后一个 `\n\n` / `。` / `\n` 的位置（相对窗口起点）；找不到则为 `-1` |
| `chunk_size // 3` | 整除阈值；默认 `600 // 3 = 200`                           |
| 判断条件              | 只有断点落在窗口**足够靠后**的位置（大约后 2/3），才按断点切开                |


为什么要设这个门槛？

- 若断点太靠前（比如窗口开头第 20 个字就有个句号），也硬切 → 这一段极短，后面碎片很多  
- 不如放弃该断点，仍切到窗口末尾 `chunk_size`，片段长度更均匀


| 情况                                | 结果             |
| --------------------------------- | -------------- |
| `cut >= chunk_size // 3`（如 ≥ 200） | 在句号/换行处切开（更自然） |
| `cut` 太小，或找不到（`cut == -1`）        | 不用断点，仍切到窗口末尾   |


这就是「尽量在语义边界切，但别切得过碎」的折中。

#### （4）Chunk 数据结构

```python
@dataclass
class Chunk:
    id: str          # "文件名#0"
    text: str        # 正文
    source: str      # 来源文件名
    chunk_index: int # 第几段
```

**精髓：** RAG 的检索单位通常不是「整文件」，而是「Chunk」。

### 4.3 `embed.py`：把文字变成向量

**知识点：Embedding 模型、归一化、`model.encode`。**

```python
@lru_cache(maxsize=1)
def _load_model(model_name):
    return SentenceTransformer(model_name)  # 只加载一次，省时间

def embed_texts(texts, model_name):
    vectors = model.encode(
        texts,
        normalize_embeddings=True,
        show_progress_bar=False,
        convert_to_numpy=True,
    )
    return np.asarray(vectors, dtype=np.float32)
```

实现的功能：

- 建库：N 段文字 → N 条向量  
- 提问：1 个问题 → 1 条向量

#### 关键代码块：`model.encode(...)` 逐参数说明

`encode` 是 SentenceTransformer 的核心方法：**输入文字，输出语义向量**。

```python
vectors = model.encode(
    texts,                       # ① 要编码的字符串列表
    normalize_embeddings=True,   # ② 是否 L2 归一化
    show_progress_bar=False,     # ③ 是否显示进度条
    convert_to_numpy=True,       # ④ 返回 numpy 还是别的类型
)
return np.asarray(vectors, dtype=np.float32)  # ⑤ 统一成 float32 数组
```


| 部分                                  | 含义                                                                                          |
| ----------------------------------- | ------------------------------------------------------------------------------------------- |
| `texts`                             | 输入列表，如 `["切片1", "切片2", ...]`；一条文本对应一行向量                                                     |
| `normalize_embeddings=True`         | 把每个向量缩放到长度为 1（L2 归一化）。归一化后 **点积 A·B = 余弦相似度**，所以 `store.search` 里可以写 `scores = vectors @ q` |
| `show_progress_bar=False`           | 服务端/教学代码里关掉进度条，避免日志刷屏                                                                       |
| `convert_to_numpy=True`             | 直接得到 numpy 数组，方便 `np.save` 存盘和矩阵运算                                                          |
| 返回值形状                               | 大约 `[N, D]`：N = 文本条数，D = 向量维度（由模型决定，常见如 384）                                                |
| `np.asarray(..., dtype=np.float32)` | 再转成 float32：更省内存，并与 `store.py` 的约定一致                                                        |


**直观理解：**  
没有 `encode`，文字只是字符串，无法算「像不像」；有了它，每段话都有了可比较的数字坐标。

**精髓：**

1. 问题和文档必须用**同一嵌入模型**，否则「不在一张地图上」，检索失效。
2. `normalize_embeddings=True` 让后续检索变成简单点积。
3. `@lru_cache`：模型很大，避免每次请求重新加载。

### 4.4 `store.py`：向量仓库 + 找最像的几段

**知识点：向量数据库（本项目是自制迷你版）、Top-K 检索。**

#### 存什么


| 文件            | 存什么             |
| ------------- | --------------- |
| `chunks.json` | 每段文字和来源         |
| `vectors.npy` | 数字矩阵 `[段数, 维度]` |
| `info.json`   | 用了哪个嵌入模型等       |


#### 检索核心（精髓代码）

```python
scores = self.vectors @ q          # 每段与问题的相似度
idx = ...取分数最高的 top_k...
return [(chunk, score), ...]
```

`@` 是矩阵乘法：一行向量 · 查询向量 = 一个分数。

实现的功能：**语义搜索**（不是关键词 `Ctrl+F`）。  
「怎么降低幻觉」和「开卷考试」靠的就是这一步找出的原文。

**精髓：**  
所谓向量库，本质就是「存向量 + 按相似度排序」。  
Chroma/FAISS 是更快/更强的同款思路；本项目用 numpy 是为了简单看得见。

### 4.6 `rag.py`：总导演（最该反复读）

**知识点：把 ingest/embed/store/llm 编排成完整业务。**

#### 建库：`rebuild_index()`

```text
列出 docs
 → ingest_paths 得到 chunks
 → embed_texts 得到 vectors
 → store.save 落盘
```

对应功能：UI「重建索引」。

#### 问答：`ask(question)`

```text
加载 store
 → embed_query(问题)
 → store.search Top-K
 → 拼「资料+问题」Prompt
 → chat(...)
 → 返回 answer + citations
```

重点代码：系统提示约束模型「资料不足就说找不到」——这是降低幻觉的产品设计，不是数学魔法。

##### 怎么拼 Prompt？代码在哪？

全部在 `**src/rag.py` 的 `ask()**` 里，检索完成之后、调用 `chat()` 之前（大约从整理 `contexts` 到传入 `messages` 那一段）。

**第 1 步：把 Top-K 命中段格式化成「资料块」**

```python
for i, (chunk, score) in enumerate(hits, start=1):
    contexts.append(
        "[资料{} | {} | 相关度 {:.3f}]\n{}".format(i, chunk.source, score, chunk.text)
    )
context_block = "\n\n".join(contexts) if contexts else "（未检索到相关片段）"
```

每一段长这样：

```text
[资料1 | rag-intro.md | 相关度 0.812]
这里是切片原文……
```

多段之间用空行 `\n\n` 拼接成 `context_block`。

**第 2 步：写 system（规则）和 user（资料+问题）**

```python
system = (
    "你是本地知识库助手。请只根据给定资料回答用户问题；"
    "若资料不足，请明确说明“资料中未找到”，不要编造。"
    "回答使用简洁中文，必要时引用资料编号如 [资料1]。"
)
user = "资料：\n{}\n\n问题：{}".format(context_block, question)
```

拼出来的 **user** 示意：

```text
资料：
[资料1 | xxx.md | 相关度 0.81]
……原文……

[资料2 | yyy.md | 相关度 0.70]
……原文……

问题：什么是 RAG？
```

**第 3 步：打成 messages 列表交给 `llm.chat`**

```python
answer = chat(
    [
        {"role": "system", "content": system},
        {"role": "user", "content": user},
    ]
)
```


| 角色       | 内容                | 作用          |
| -------- | ----------------- | ----------- |
| `system` | 助手身份 +「只根据资料答」等规则 | 约束行为，降低瞎编   |
| `user`   | `资料：…` + `问题：…`   | 提供开卷材料与用户问题 |


这就是流水线里「拼 Prompt」的全部含义：  
**不是另有神秘模板文件，就是 `rag.py` 里用字符串把检索结果和问题拼进 `messages`。**

同时循环里组装的 `citations` 会随接口返回前端展示，**不发给模型**（模型只看 `system` + `user`）。

**精髓：**  
RAG 工程 = **检索质量** + **Prompt 约束** + **引用展示**。  
三者缺一，用户体验都会差。

## 第 5 章：一次完整请求的「动画片」

假设你问：「什么是 RAG？」

1. 浏览器 `POST /api/ask`，body：`{"question":"什么是 RAG？"}`
2. `app.py` → `rag.ask()`
3. `embed_query` 得到问题向量 q
4. `vectors @ q` 算出每段分数，取出最高几段（例如来自 `rag-intro.md`）
5. 拼 Prompt：系统规则 + `[资料1]原文...` + 问题
6. `llm.chat` 调用 DeepSeek
7. 返回：
  - `answer`：模型组织的中文回答  
  - `citations`：用了哪些原文、分数多少
8. `app.js` 显示回答，下面附引用

如果你跳过建索引：第 4 步没有 vectors → 直接报错「尚未建立索引」。

## 第 6 章：容易混淆的点（新手避坑）


| 误解                     | 正解                             |
| ---------------------- | ------------------------------ |
| 上传了就能问                 | 还要重建索引                         |
| 删了文件索引就变了              | 删的是 docs；需重建索引才更新 index        |
| Embedding 和 LLM 是同一个模型 | 不是。一个管「变成向量」，一个管「写回答」          |
| 相关度分数低就一定错             | 低只表示不够像；仍可能被 Top-K 选中带进 Prompt |
| RAG 保证不幻觉              | 只能**降低**；还靠 Prompt 约束和资料质量     |
| 向量库很神秘                 | 本项目就是「数组 + 点积排序」               |

## 第 7 章：你该掌握的「精髓清单」

如果只能记住 8 条，记这些：

1. **RAG = 先检索原文，再生成答案。**
2. **检索单位是 Chunk，不是整本书。**
3. **Embedding 把语义变成可比较的向量。**
4. **同一问题/文档必须同一嵌入模型。**
5. **归一化后，点积就是相似度。**
6. `**rag.py` 是业务精髓，其它文件是零件。**
7. **LLM 只看见你塞进 Prompt 的内容。**
8. **引用（citations）让答案可验证，这是产品精髓。**

## 第 8 章：建议动手练习（真正学会）

按顺序做，每做一步对照代码：

1. 往 `data/docs/` 再丢一个自己的 `.md`，重建索引，提问这篇里的内容。

5. 打开 `data/index/chunks.json`，亲眼看切片长什么样。
